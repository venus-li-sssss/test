# QDM562 串口辨识（实测证据版）

换机器、换治具、换 USB 线之后，**第一件事就是认口**。认错口的代价：脚本读不到 GNSS 版本、上位机打不开串口、日志抓半天是空的。

## 一、四个模组口的中文判据

设备（EG800AKCN_91LC / ASR1602S）插上后，Windows 会枚举出 4 个 Quectel 口 + 你想接的 USB-232 口：

| 设备名 | 判据（怎么确认是它） |
|---|---|
| `Quectel USB AT Port` | 发 `AT` 有 `OK`；`ATI` 回 `Quectel` + `EG800AKCN_91LC` + `CustRevision ... _764`；`AT+CGMM` 也能回机型 |
| `Quectel USB DIAG Port` | 没有 AT 应答；CATStudio 能选到它并录 CAT LOG；被 CATStudio 占用时，别的程序打开会报被占用 |
| `Quectel USB MI05 COM Port` | 一开就持续刷 `Monitor` / `LOC LOC_GNSS_FIX` / `$NAVVEL` / `$PDTINFO` / `FWVer` / `ver:0765`；**这就是串口日志口**，升级脚本的 `gnss_com` |
| `Quectel USB Modem` | 用来拨号/发短信的口，本项目用不到 |

> 端口号本身不固定：换 USB 口/换机器可能从 COM29 变成 COM2x。**永远按设备名认，不要按 COM 号认**。

## 二、外接两个 USB-232 口（长得一模一样，最容易搞混）

`USB Serial Port (COMx)` 有两个来源：debug 口、上位机口。区分方法：

1. **debug 口**（本项目 = `COM3`）
   - 波特率 115200 8N1 无流控；
   - **平时完全静默**（连开机都要碰运气才有几行）；
   - 只有**设备重启或升级过程**才会打印；
   - 打印内容像内核/驱动日志：`[quec_uart_open][416]The ...` / `Error: i2c_wait_status time out` / `$RESET,0` / `$PDTINFO`。

2. **上位机口**（本项目 = `COM184`）
   - 走 5A A5 私有协议，是升级/压测的口；
   - 未升级前设备**不回帧**：往它发 `5A A5 01 3E 09 01 02 02 B2 FF`，串口日志口（COM29）立刻出现 `_5AA5 Receive 5AA5 cmd:len:1,src:3e,dst:9,cmd:1,index:2,data:2.`，但 184 自己 `rx=0`、设备日志也没有 `5AA5 Send` —— **这是正常的单向语义**，别当成"线接反了/设备坏了"；
   - 历史可用的双向证据：`upper_log_*.txt` 里同时有 `[Tx] 5A A5 01 3E 09 01 02 02 B2 FF` 和 `[Rx] 5A A5 01 09 10 01 00 22 C2 FF`。

## 三、三步认口（可直接照做）

```powershell
# ① 列出端口与设备名
Get-CimInstance Win32_PnPEntity | Where-Object { $_.Name -match 'COM\d+' } | Select-Object Name,Status

# ② 对版本串（AT 口）
#    用 QCOM/串口工具发 ATI，看机型与 CustRevision

# ③ 抓一次开机日志（谁在出 $PDTINFO，谁就是串口日志口）
#    抓取工具：C:\QDM562\日志抓取\日志抓取.exe /auto /port:COMx /baud:115200 /mode:text /dir:...
#    然后给设备断电重上电
```

④ 找上位机口：发一帧 5A A5（见上），观察串口日志口是否出现 `_5AA5 Receive`。

自动版：`python scripts/port_probe.py`（脚本会枚举、分类、写版本帧、读日志求证，并给出要写进 `device.yaml` 的字段值）。

## 四、认错的典型症状对照

| 症状 | 多半是 |
|---|---|
| 抓了半天 0 字节，设备确实在跑 | 抓到的是 debug 口（`COM3`）而它在静默 —— 换 `COM29` 抓 |
| 抓取工具一直红字重试、打不开 | 该口被别的程序占着（脚本 `qdm562cap` / CATStudio / 上位机 GUI） |
| 上位机"打开串口"失败 | `COM184` 被抓取或别的工具占着；先 `/killall:` 或关窗口 |
| AT 有应答但 `ATI` 数字和实际版本不一致 | ATI 的 `_764` 是遗留串，真版本看串口日志 `ver:0765` |
| 升级脚本 GNSS 校验总读不到 Build | `gnss_capture_port` 填错口，或脚本按写死的 `com48_*.log` 找文件 |
