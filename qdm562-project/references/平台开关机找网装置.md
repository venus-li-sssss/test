## 二、端口（本机实测，换机器必须重新认）

| 口 | 角色 | 关键事实 |
|---|---|---|
| COM22 | 继电器板（CH340，9600） | `A0|通道|状态|校验`；NC 接法：状态 1=断电、0=上电 |
| COM25 | 上位机口（FTDI，115200） | 5A A5 协议，DUMP 版本帧有应答 |
| COM27 | debug 口（FTDI，115200） | 平时全静默，只有断上电/升级才打 `$RESET` / `$PDTINFO` / `quec_uart_open` / `CHIP_ID: 0x1605` |
| COM29 | 串口日志口（Quectel） | 一直刷 `Monitor`/`LOC`，含 `ver:0765` |
| COM28 | AT 口 | `AT+CGSN` 读 IMEI |
| COM31 / COM30 | DIAG / Modem | DIAG 一开就刷二进制 CAT；Modem 用不到 |

## 三、DUMP（版本查询）

**先分承载，别一上来就发 5A A5**（2026-11-23 没上位机口却发 5A A5，白等两轮）：

| 承载 | 前提 | 发什么 |
|---|---|---|
| **AT 口三连（首选）** | 模组 USB 插着（`Quectel USB AT Port` 自己枚举） | `AT+QDUMPCFG=0,0` / `AT+QDUMPCFG=2,0` / `AT+LOG=19,1`，三条都回 `OK`；**AT 口不回版本**，版本看日志口 `ver:xxxx` |
| 上位机 5A A5 帧 | 装置里挂了上位机 FTDI（115200） | 下面的帧 |

发送（源码里叫 `build_version_cmd`，与上位机 GUI 的版本/Dump 一致）：

```
5A A5 01 3E 09 01 02 02 B2 FF
      LEN=01 SRC=3E DST=09 CMD=01 PARAM=02 02 | 校验=~sum(小端)
```

应答：

```
5A A5 02 09 3E 04 02 65 07 44 FF
              └┬┘ └┬┘
             CMD=04  data=65 07
```

**版本 = 两字节反序**：`65 07` → `"{:02X}{:02X}".format(d[1], d[0])` = **0765**。
设备还会周期性发心跳 `5A A5 00 09 01 7B 00 7A FF`（不是应答，别拿去解析版本）。

注意：`ATI` 回 `CustRevision ..._764` 是历史遗留串，真版本以 **AT 三连后的日志口 `ver:xxxx`** / 5A A5 DUMP 应答 为准。

## 四、三个必踩的坑（都已修在 `开关机找网抓取.py`）

1. **断电瞬间 COM29 掉枚举** → `ser.read()` 抛
   `serial.serialutil.SerialException: ClearCommError failed (PermissionError(13, '设备不识别此命令'))`，
   线程直接死、日志变 0 字节（但文件里可能已有半截内容，看着"有数据"其实没抓完）。
   修法：`read()` 单独 try/except → break 出内层 → 关串口 → 500ms 后重连；重连时若原号打不开，
   枚举 `hwid` 含 `2C7C` 且描述不含 AT/DIAG/Modem 的口找回（换号也能抓）。
2. **DUMP 发太早**：上电 3s 内设备还没起来，帧发出去无应答。
   修法：上电后等 6s，再每 1.5s 重发一次，窗口 14s；拿到 `5A A5 02 09 3E 04 02` 头即返回。
3. **debug 口 0 字节不是没抓**：它平时静默，只有断上电/升级才打印；判活看有没有开机行
   （`CHIP_ID` / `PlatInfo` / `$RESET`），不看文件大小。

## 五、跑法（已验证可持续长跑）

**第一步：官方带界面工具双口常驻抓日志（首选，用户要求"要界面的"）**

```powershell
$py = "C:\Users\DELL\AppData\Local\Programs\Python\Python39\python.exe"
& $py "C:\QuecAgentTools\日志抓取\scripts\capture_serial_log.py" --ensure-tool-only
& $py "C:\QuecAgentTools\日志抓取\scripts\capture_serial_log.py" `
  --targets "debug|COM27|115200|text;serial|COM29|115200|text" `
  --instance qdm562 --live-dir "D:\QDM562\平台开关机找网\日志\live" --launch
& $py "C:\QuecAgentTools\日志抓取\scripts\capture_serial_log.py" --status
```

- 工具实体 `C:\QuecAgentTools\串口日志抓取\串口日志抓取.exe`（v3.8，**exe 只能放 C 盘**，D 盘/桌面会被 Bitdefender 秒删）；启动后窗口标题应为「串口日志抓取 v3.8 —— 多串口 + RTT(J-Link) / 16进制 / 命令行」。
- 不给 `--sec` = 常驻；`--stop` 停。**`status.json` 在 `--live-dir` 里**（`日志\live\status.json`），不在工具目录，；磁盘 `.log`/`current_size` 为 0 是缓冲写，看 `totals.bytes` 和每个 target 的 `bytes`。
- 实测：断电瞬间 COM29 掉枚举由工具自己重连，`serial reconnects=1` 后继续抓，无需人工。

**第二步：继电器断上电 + DUMP 取版本**

```powershell
cd D:\QDM562\平台开关机找网
python qdm562_平台开关机脚本_V01.py --validate        # 配置校验，不联网不动继电器
python 一轮_继电器与DUMP.py                            # 一轮：断电2s→上电→等6s→COM25 DUMP
python 开关机找网抓取.py --cycles 1 --capture 32      # 备用：无界面一体轮次（继电器+双口+DUMP）
python 开关机找网抓取.py --cycles 0 --capture 32      # 备用：无限循环挂测
```

`开关机找网抓取.py` 自写版本**只作无界面批量轮次的备用手段**，不要拿它替代官方 exe 抓日志（用户明确否决过自写抓串口）。

**启动三铁律**：

1. **python 必须写绝对路径**：`C:\Users\DELL\AppData\Local\Programs\Python\Python39\python.exe`。
   本机 PATH 里排第一的 `python` 是 LarkShell 沙箱运行时，从 cmd/bat/用户窗口调用会「命令找不到」或没装 pyserial，表现就是"工具没运行"。
2. **只能开一个抓取实例**：COM27/COM29 独占，多开会互相抢口（症状：一方日志 0 字节、另一方抓不到）。
3. **判活看 `status.json` 的 `bytes` 是否在涨**，别按秒看"没动静"就判死；debug 口平时静默正常。

**产物目录**
- 官方工具：`日志\live\debug_<ts>.log`（debug 口，每轮开机段约 12KB）+ `serial_<ts>.log`（日志口，整轮刷）+ `status.json`
- 自写 runner（备用）：`日志\持续_<时间戳>\cycleNN_debug_com27.log` / `cycleNN_device_com29.log` / `运行输出.txt`
