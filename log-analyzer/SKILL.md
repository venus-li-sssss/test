# Log Analyzer

## Overview
本技能提供专业的日志分析能力，能够自动识别日志中的错误、异常、失败模式，支持多源日志关联分析，帮助快速定位问题根因。

## 适用场景
当用户提出以下类型的请求时，自动触发本技能：
1. 单日志文件分析：仅提供1份日志文件，要求分析错误、统计结果、定位根因
2. 多源日志联合分析：同时提供设备日志 + 脚本日志，要求结合两者分析问题
3. 带指南的深度分析：提供设备日志 + 设备日志指南 + 脚本日志，要求按照指南规范分析问题
4. 故障排查：提供错误现象和相关日志，要求定位故障点和解决方案

## 核心能力
### 1. 单日志文件分析流程
1. **初步识别**：判断日志类型（脚本日志/设备日志/系统日志/服务日志）
2. **异常检索**：自动识别日志中的错误、异常、失败关键词（错误、ERROR、FAIL、Exception、Traceback、failed、timeout等）
3. **统计汇总**：统计运行次数、成功次数、失败次数、成功率、运行时长等核心指标
4. **模式识别**：识别重复出现的错误模式、时间分布规律
5. **根因定位**：基于错误上下文分析故障原因

### 2. 设备日志与脚本日志联合分析流程
1. **分别分析**：先独立分析设备日志和脚本日志，各自提取错误信息和异常点
2. **时间对齐**：按照时间轴对齐两份日志的事件序列
3. **关联匹配**：匹配脚本侧的指令下发、状态查询与设备侧的响应、执行结果
4. **链路还原**：还原从指令下发到设备执行的完整失败链路
5. **根因定位**：明确故障是发生在云端/网络/设备/脚本哪个环节

### 3. 分析输出规范
所有分析结果必须包含以下内容：
- 整体运行概况（总次数、成功/失败次数、成功率、运行时长）
- 失败原因分类统计
- 逐次失败详情（时间、具体错误、根因）
- 成功案例汇总（如果有）
- 共性根因总结
- 优化建议（可选）

## 错误码对照表
### 设备端MQTT错误码
- `-8,206`：升级包断点续传失败
- `check fail 8`：升级包完整性校验失败
- `request region url failed -8`：升级服务器地址请求失败
- `ota timeout ack reset`：OTA超时触发重置
- `http post error code = 0`：网络请求失败

### 脚本侧错误码
- `statuscode:201`：升级指令下发成功但状态检查失败
- `FOTA升级状态检查失败`：多模块升级未全部完成

5. 输出分析报告：包含运行概况、失败统计、根因分析

4. 输出关联分析报告：包含失败链路、根因定位、优化建议
