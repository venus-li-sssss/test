# 路测场景截图（QGIS 无界面出图）

把一次路测的**高精度日志 + 设备日志**出成报告能直接用的三件套（2026-09-29 用户定的契约）。

**一句话契约**：输入 = **设备 NMEA + 对比(高精度) NMEA + 区域划分**（KML 多边形 / 时间段 / 帧编号，三选一，KML 优先）。
**用户只给日志没给区域划分时，必须先主动问（见硬规则第 7 条），禁止闷头留空跑完让用户自己发现没分区**——
用这个 skill 的人不一定知道"区域划分"是输入项。
→ 输出 = **① 对比轨迹 KML**（导入图新地球等工具交互查看）+ **② 截图**（整体截图 / 区域整体截图 / 区域分段截图，肉眼看）
+ **③ CEP 表 Excel**（行=CEP60/65/…/95 每 5 一档，列=整体 + 各场景区域，格子=该百分位的同刻距离(m)）。

同刻连线上的距离白字**默认开**（截图里带黑描边，好看好读）。

| 产物 | 文件 | 用途 |
|---|---|---|
| ① KML | `对比轨迹_<时间戳>.kml` + 两个图钉 png | 导入**图新地球**（也可 Google Earth / 奥维 / QGIS）缩放查看、点气泡看时间/距离/高度差；含黄线、红线、白同刻连线、距离白字、区域边界 |
| ② 截图 | `整体\整体.jpg`、`<区域>\区域整体.jpg`、`<区域>\01_160319.jpg …` | 肉眼看/贴报告。每段约 `seg_m` 米，**编号全局连续**，文件名带起始时间 |
| ③ CEP 表 | `CEP_列表.xlsx`（2 个 sheet：`CEP` + `说明`） | 行=CEP60…95，列=整体+各区域，格=该百分位同刻距离(m)；`说明` sheet 有每列样本数 |

外加 `帧清单.txt`（编号 ↔ 起始时间 ↔ 所属区域），便于用户"按编号"指定区域。

## 一条命令跑

```cmd
cd /d D:\OSGeo4W\bin
python-qgis-ltr.bat "<skill目录>\scripts\路测截图生成.py" "<区域划分.json 路径>"
```

不传参数则用 `scripts\区域划分.json`。改配置**不需要**改代码。运行中用 `os._exit(0)` 退出，避免 QGIS 析构卡死。

### 三件套的实现要点

**① KML**（`write_kml()`）

- 结构：`Document > Folder Tracks > 1.高精度(黄) / 2.设备(红) / 3.同刻连线(白) / 4.同刻距离标注 / 5.区域边界`。
- **定位点默认带**（`kml_points=true`）：每个定位点一个 Placemark，气泡=本地时间/经纬度/海拔/速度/卫星数/HDOP/定位质量，
  `<name>` 留空（地图上不出文字）、`LabelStyle` scale 0，只有**点一下**才弹气泡。
  体积 4256+4152 点 ≈ 10 MB（图新地球首次转 LCAD 1~3 分钟）。**要"点得动、点得开"就别关它**——
  用户 2026-09-29 反馈过一次"KML 没有定位点、点不出来"，就是因为我默认给关了。
- 白连线 `<name>21.6 m</name>`，气泡里是 本地时间 / 同刻距离 / 高度差 / 两端坐标（口径与「轨迹对比-图新地球」那套一致）。
- **距离白字默认每条同刻线都标**（`kml_label_every=1`），只有**静止/重叠**的那批被掐掉：
  KML 里"是否重叠"跟缩放有关、没法按屏幕像素算，所以用 `labels.py::dedupe_by_dist()`
  **按地面距离去重**（中点相距 < `kml_label_min_sep`（默认 5 m）只留一个）。
  实测（0924）：830 条连线 → 标 387 条；丢掉 443 条的**唯一原因**是那份数据有一段 19 分钟原地静止，
  455 个连线中点彼此相距中位 **0.1 m**（全挤在一个点上），本来就不可能都看清。
  正常行驶（5 s 走 >5 m，即 >3.6 km/h）一条都不会丢。想让静止段也全标 → `kml_label_min_sep: 0.5`。
- 注意两套挑字机制**不一样、别混**：截图用 `pick_labels()`（按**屏幕像素**、图幅越粗越疏，因为 PNG 分辨率固定）；
  KML 用 `dedupe_by_dist()`（按**地面距离**，因为 KML 缩放随时变）。
- 图钉：从 `kml_exe` 的 `Resource\image\GEMarker` 把 `ylw-blank.png`/`red-blank.png` 拷到**输出目录**，href 写 `./xxx.png`
  → **KML 和两个 png 放在同一目录才是自包含的**；单独把 KML 拎给别人会丢图钉（线、白连线、气泡仍在）。
- **颜色必须用 KML 的 `aabbggrr`，不是 CSS 的 `#rrggbb`**：直接把 `#ffffff` 写进 `<LabelStyle><color>` 是**非法值**
  （会画黑或忽略），脚本用 `kml_color()` 转（白 `#ffffff` → `ffffffff`）。**这个坑踩过**。

**③ CEP 表**（`write_xlsx()`）

- 口径：CEP_p = **同刻距离的第 p 百分位**（线性插值，等同 Excel `PERCENTILE.INC`），单位米；**行号就是 p**。
- 列：`整体`（全部同刻点）+ 每个区域；**区域归属复用截图那套帧归属**（同刻点按时间落到帧 → 帧属于哪个区域就归哪个区域），
  所以 Excel 里每个区域的数字和截图里的区域是**同一批点**。
- 样本数放 `说明` sheet（每列多少同刻点），不污染主表。
- **xlsx 是标准库手写的**：QGIS 的 python **没有 openpyxl 也没有 pip**，所以 `write_xlsx()` 直接拼
  `[Content_Types].xml` / `workbook.xml` / `worksheets/sheetN.xml` 打成 zip。改它之后**必须回读验证**——
  用有 openpyxl 的那个 python（`C:\...\Python310\python.exe`）跑 `openpyxl.load_workbook()` 看能不能读出来。

## 区域划分：三种方式，KML 优先

优先级由脚本自动判定：**`kml_dir` 目录里只要有 `.kml` 就按 KML 划；没有才按 `mode` 走时间/编号。**

| 方式 | 用户怎么给 | 配置 |
|---|---|---|
| ① KML（优先） | 图新地球「绘制/手绘」画多边形圈区域 → 右键图层导出 KML → 丢进 `kml_dir`（或直接发我） | `"kml_dir": "D:\\work\\路测工具\\区域KML"`；区域名取 KML 里 Placemark 的 name，或文件名 |
| ② 时间 | "16:21:30~16:29:00 是小区" | `"mode":"time"` + `regions_time: [{name, ranges:[[起,止],…]}]` |
| ③ 帧编号 | 先跑一遍拿编号，再说"第X帧~第Y帧是小区" | `"mode":"image"` + `regions_image: [{name, from, to}]`（`regions_image` 为空时会先输出 `0_全部帧\` 全部编号帧） |

KML 模式逐帧统计"该帧轨迹点落在多边形内的比例"，取比例最高且 ≥ `kml_min_ratio`（默认 0.3）的区域，落不进去的帧进 `其他\`。

## 硬规则（用户明确要求，别自作主张）

1. 只出这三种图，**不做拼图、不做网格缩略图**。
2. **每张截图都要画整条轨迹的全部点**（黄=高精度、红=设备），绝不按段抽样——"其他点消失"会被投诉。白线=同刻连线，每 5 秒一条；
   **白线上带距离白字（默认开）**，字落在连线中点，白字+黑描边；**同一处只留一个、图幅越粗自动越疏**（防止静止段叠成一坨）。
3. **帧编号全局连续**（01→N），文件名 `编号_起始时间.jpg`，用户靠它判断顺序；不要按场景重新编号。
4. **一个区域必须是连续帧段**。若某区域帧号跳号（脚本会打 ⚠），它的"区域整体截图"会把别的区域框进来——遇到就拆成 `大马路(北)/大马路(南)` 这样的两个区域。
5. 分段图统一 **0.32 m/像素**（z≈19 最细档）；单图压到 **<2MB**（对话显示上限），脚本会自动降质量。
6. 不要一次把几十张图塞进对话（会把上下文冲爆，`run_tool_batch(last_only=True)` 也拦不住）：交付方式 = 打开目录 + 发 2~3 张样张，其余按用户点名的场景/编号再发。
7. **区域划分必须主动问，不能等用户想起来**。收到日志而区域划分没给时，**先停下问一句**（话术见典型流程第 1 步），
   并给出三条路 + 一个兜底：①图新地球手绘多边形导出 KML（最准）②报时间段 ③报帧编号（可以先跑首遍拿帧清单）
   ④"不清楚就让我按数据特征（静止段/信号丢失段/高速段）预分一个草稿，你再修正"（草稿只用两条日志就能出，**不需要先有图**）。
   只有用户明确说"不用分区/先跑一遍看效果"才允许留空划分交付；交付无分区结果时也要把"下一步可以分区"的选项再提醒一次。
   （2026-11-02 用户反馈：只给日志直接跑完后，别人意识不到还能按场景分区、CEP 还能分列。）

## 技术要点 / 踩过的坑

- **QGIS**：本机装在 `D:\OSGeo4W`（LTR 3.44，`python-qgis-ltr.bat`）。未装则静默安装：
  `osgeo4w-setup.exe -q -k -S -n -N -P qgis-ltr -R D:\OSGeo4W -l D:\OSGeo4W\pkgs`（`-k` 必带，缺了会秒退 exit1；装到 D 盘不需要管理员）。
- **图层顺序**：`QgsMapSettings.setLayers` 是**自上而下**，影像底图必须放**最后**，否则影像盖住轨迹。
- **矢量图层从 NMEA 建内存图层**：直接加载 KML 会得到 0 个要素（0 条线）。NMEA 解析用同目录 `nmea.py`（`nmea.parse()` + `nmea.build_epochs()`）。
- **底图**：默认 Esri 全球影像 XYZ（`zmax=19`，z=20 无影像会灰）。要换源改 `xyz_url`；同一位置 Bing 影像可能更锐（Laplacian 约 2 倍），但需自己提供可用的 XYZ/quadkey 地址。
- **不要试图用图新地球自动截图**：它的可视范围由 KML LookAt range 决定，滚轮/双击/拖拽/搜索框在后台都不可精确控制，取景不是太远就是偏；出图走 QGIS 无界面渲染。
- 分辨率：`mpp = max(0.32, sqrt(宽_m × 高_m / pix_max))`，即一张图最多 `pix_max`（默认 400 万）像素。整条轨迹一张图约 1.1 m/px，250 m 小段可到 0.32 m/px。
- 自检：脚本对每张图统计黄/红/白像素并打印；`黄+红=0` 会打 `!! 警告`。判断"轨迹线画上去了"看这个，不用逐张看图。
- **同刻距离白字（QGIS 标注）**：单独一个 Point 图层 `同刻距离(白字)`，符号全透明、只出文字；
  `QgsPalLayerSettings` + `QgsTextFormat`(+`QgsTextBufferSettings` 描边) + `QgsVectorLayerSimpleLabeling`。
  两个关键点：①**标注层必须放 `STACK` 最前面**（STACK 自上而下，放后面会被点/线压住）；
  ②QGIS 的文字**有 buffer（描边）**，这是它比 KML 强的地方——KML 的 LabelStyle 只有颜色+字号、没法描边，白字在亮影像上会发虚。
- 标注密度：字体是**固定像素大小**，所以同一份数据在 `整体截图`（约 1.1 m/px）上比 `分段图`（0.32 m/px）显得挤得多。
  `labels.py::pick_labels()` 负责自动挑字（纯 python，不依赖 QGIS）：把候选按**同刻距离从大到小**排序，
  只有与已选字的**屏幕框不重叠**才留下；屏幕最小间隔还要乘 `gap = max(1, mpp/0.32)`
  （分段图 gap=1 保持全标，整体截图 gap≈3.5 自动稀疏）。
  效果（0924 实测）：静止段（连线中点几乎重合）15 个字 → 只剩 1 个；整体截图 830 个候选 → 只画 64 个；
  分段图仍按原样全标。想人工再控就调 `label_every` / `label_min`；`label_all=true` 则跳过挑字全画。
- 改过挑字规则后**不用开 QGIS 就能验证**：`python scripts/test_pick_labels.py`（`labels.py` 是纯 python，
  测试直接 import 它，自带三条断言：静止段不叠、分段图全标、整体图变疏）。
- **改本 skill 的 .py 时注意安全扫描**：`qwenpaw skills test` 会把技能判 safe/unsafe。
  **别把路径先存进变量再 `open(变量)`**（`p = os.path.join(...)` 然后 `io.open(p)`）——会被当成"任意文件读取"判 **unsafe**，
  整个技能不通过。要写成 `io.open(os.path.join(...))` 一次成型。（2026-09-29 在 `check_artifacts.py` 上踩到，
  做包 skill 的 `make_full_fbfmake.py` 里也有同一条注释。）
- 日志编码/时间：设备日志为北京时间，高精度日志为 UTC，按 UTC 秒配对算同刻连线。

## 典型流程

1. 用户给两条日志（没提区域划分）→ **先主动问**，不要直接开跑。参考话术：
   "这次路测有哪些测试场景要分区吗（如 公司周边/大马路/小区/村子/地下停车场）？可以：①在图新地球手绘多边形导出 KML 给我（最准）②直接报时间段 ③报帧编号（不知道编号我可以先跑一遍全部帧给你挑）④记不清范围的话，我按数据特征（静止段/信号丢失段/高速段）预分草稿你再改。不需要分区也行，但 CEP 表就只有整体一列。"
2. 拿到划分（KML / 时间 / 帧编号）→ 填进 `区域划分.json` 跑 → 整体 + 各区域整体 + 各区域分段 + CEP 分列。
   用户选"按帧编号"但不知道编号 → 这时才先跑 `mode=image`（`regions_image` 留空）拿 `0_全部帧\` + `帧清单.txt`，发 2~3 张样张让用户对着编号圈区域。
   **首遍是"点区菜单"，不是最终交付**：帧编号是"先有蛋"的——编号要跑一遍才有，所以首遍跑完必须**当场追问**
   "第几帧~第几帧是什么场景？"（每帧文件名带起始时间，用户报时间也行 → 改 `mode=time`，不必对图）；
   用户连时间也记不清 → 按 NMEA 特征（静止/信号丢失/高速）分析出预分草稿，直接给建议帧号区间等确认。
   把"其他 N 帧"当最终结果交付而不追问 = 事故（2026-11-02 踩过，用户原话：别人使用可能意识不到这点）。
3. 打开输出目录（`explorer`）交付**三件套**：① `对比轨迹_*.kml` 给用户导进图新地球看 ② 截图贴报告 ③ `CEP_列表.xlsx` 交表格；
   把 `帧清单.txt` 一起给，按需再点名发图。
4. 收图前**至少看一张分段图**确认：白线上有白字距离（默认开）、字压得住底图。没字 → 查 `label_lines` 是否被设 false；
   看不清 → 查 `label_buffer`（描边）是否被关、或调大 `label_size`。
5. 交 KML 前确认 XML 合法、`<LabelStyle><color>` 是 `aabbggrr`（白=`ffffffff`）；交 Excel 前用有 openpyxl 的 python 回读一次。

## scripts

| 文件 | 用途 |
|---|---|
| `路测截图生成.py` | 主脚本（QGIS）：出 KML + 截图 + CEP 表。用 `python-qgis-ltr.bat` 跑 |
| `labels.py` | 同刻距离白字的挑字：`pick_labels()`（截图用，按屏幕像素）+ `dedupe_by_dist()`（KML 用，按地面距离） |
| `nmea.py` | NMEA 解析（`parse` / `build_epochs`，`FIXQ`） |
| `test_pick_labels.py` | `labels.py` 的离线单测（不需要 QGIS），自带 3 条断言 |
| `check_artifacts.py` | 三件套体检：KML XML/颜色/href + xlsx 回读 + 有没有截图目录（需要 openpyxl 的那个 python） |
| `区域划分.json` | 配置模板（区域划分 + 白字 + KML + CEP 全部可配） |
| `scene_shots.py` / `verify_shots.py` | **旧版**：自绘瓦片引擎，不需要 QGIS 的兜底方案 |
